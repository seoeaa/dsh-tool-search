# dsh-tool-search

[English](README.md) | **Русский**

Поиск и загрузка инструментов по запросу в DeepSeek Harness. Полный каталог хранится на сервере, а агент получает только инструменты, нужные для текущей работы.

Этот форк расширяет [lordqyxz/dsh-tool-search](https://github.com/lordqyxz/dsh-tool-search): добавлены компактная конфигурация по умолчанию и совместимость с Harness **0.2.1-alpha.5**.

## Как это работает

1. Агент начинает с `tool_search` и основных инструментов, например `skill` и `ask_user_question`.
2. Перед выбором инструментов для новой задачи или возможности агент ищет их по действию и имени сервиса.
3. Поиск возвращает до **3 подходящих инструментов** вместе со схемами параметров.
4. Агент вызывает выбранный инструмент по исходному имени через обычный механизм исполнения Harness.
5. Каждый агент сохраняет до **6 найденных инструментов**. Старые находки уступают место новым; при необходимости их можно снова найти и загрузить.

По умолчанию полный каталог, включая имена и описания, не попадает в промпт. Поиск выполняется локально по доступным вызывающему агенту инструментам, включая MCP, и не требует дополнительного API-ключа.

Вызов скрытого инструмента до поиска отклоняется с подсказкой сначала найти его. Для повторного использования загруженного инструмента новый поиск не нужен. Проверка аргументов, разрешения, согласования, guards и тайм-ауты продолжают действовать.

## Установка

Требуются Harness **0.2.1-alpha.5**, Cordis **4.0.5** и Node.js **22.19+ в ветке 22.x либо 24+**. Другие версии Harness не проверялись.

В менеджере плагинов Harness установите пакет по ссылке и включите bundle:

```text
https://github.com/seoeaa/dsh-tool-search/releases/download/v0.1.1/dsh-tool-search-0.1.1.tgz
```

Архив релиза содержит собранный JavaScript и объявления типов. Не включайте одновременно другой плагин, регистрирующий `tool_search`.

Для разработки или установки из исходников:

```bash
git clone https://github.com/seoeaa/dsh-tool-search.git
cd dsh-tool-search
pnpm install --frozen-lockfile
pnpm run build
```

Установите полученный локальный каталог через менеджер плагинов Harness. Применение без перезапуска зависит от поддержки HMR в хосте; проверяйте результат применения в менеджере.

## Настройка

Входящий в пакет `cordis.patch.yml` включает следующую конфигурацию:

```yaml
- insert:
    - id: tool-search
      name: dsh-tool-search
      config:
        threshold: 1
        maxResults: 3
        maxDiscovered: 6
        residentCatalog: false
        requireDiscovery: true
```

Изменить значения можно в настройках плагина в Harness.

| Параметр | Значение bundle | Назначение |
| --- | --- | --- |
| `toolName` | `tool_search` | Имя инструмента поиска. |
| `alwaysVisible` | `skill`, `ask_user_question`, `report`, `submit_*`, `structured_output*` | Шаблоны имён инструментов, доступных без поиска. |
| `threshold` | `1` | Минимальное число откладываемых инструментов для включения фильтрации. |
| `maxResults` | `3` | Максимальное число полных схем в одном результате поиска. |
| `maxDiscovered` | `6` | Максимальное число загруженных находок; не меньше `maxResults`. |
| `residentCatalog` | `false` | При включении добавляет в промпт список скрытых имён и кратких описаний. |
| `requireDiscovery` | `true` | Запрещает прямой вызов скрытого инструмента до поиска. |
| `charactersPerToken` | `4` | Число символов на токен для оценки стоимости схем. |
| `descriptionChars` | `110` | Ограничение описания в необязательном каталоге промпта. |
| `deferToolGuidance` | `true` | Убирает разделы промпта, посвящённые скрытым инструментам. |

В таблице указаны действующие **настройки bundle**. При прямом использовании `apply()` сохранены исходные резервные значения: `threshold: 15`, `maxResults: 5`, `maxDiscovered: 20`, `residentCatalog: true`.

`alwaysVisible` заменяет весь исходный список: при расширении сохраняйте стандартные шаблоны. Зарезервированный транспорт `run_code` не откладывается.

## Пример поиска

Найдите инструмент по возможности:

```json
{"query":"read text file first lines","max_results":1}
```

Если в результате есть встроенный `read`, вызовите его по возвращённой схеме:

```json
{"file_path":"README.md","offset":1,"limit":20}
```

Используйте точное действие, название сервиса или полное имя инструмента. Английские ключевые слова помогают, если описания написаны на английском. Поиск лексический: если результаты не подходят, переформулируйте запрос.

## Отличия от исходного проекта

- Сборка промпта адаптирована к `AssembleContext.scope`; сохранён запасной путь для прежнего поля `agent`.
- Добавлен `residentCatalog: false`: имена и описания также могут оставаться на сервере.
- По умолчанию ограничено число найденных схем; повторный поиск обновляет порядок находок.
- При программных вызовах найденные схемы остаются в SDK и не объявляются как native-вызовы рядом с `run_code`.
- Зависимости и overrides согласованы с проверенной версией хоста.
- Добавлена документация на английском и русском.

Состояние поиска разделено по агентам и восстанавливается из успешных результатов поиска в событиях сессии. История выпуска — в [CHANGELOG.md](CHANGELOG.md).

## Проверка и ограничения

Адаптация прошла сборку, проверку типов и **17 существующих проверок исходного проекта**. В работающем native-сеансе успешно выполнена цепочка `tool_search` → `read` → содержимое файла. Отдельно проверены независимое состояние двух агентов, ограничение числа схем, вытеснение, повторный поиск и сохранение обычных runtime guards после поиска.

В одной локальной проверке начальный JSON со схемами сократился с **674 схем / 1 230 070 байт** до **3 схем / 2 093 байт**. После одного поиска он содержал **4 схемы / 2 711 байт**. Это размеры раздела инструментов, а не гарантия для любой установки и не размер всего запроса.

- Найденный инструмент может иметь большую схему: ограничивается число инструментов, а не число байт.
- Прежние результаты и переписка остаются в старых сессиях до обычного сжатия.
- Проверено native-исполнение. Для программных вызовов проверена сборка SDK; полное исполнение в этом режиме не проверялось.
- Инструмент может находиться через поиск, хотя сервис, исполняемый файл или учётные данные недоступны.
- Отключение bundle возвращает обычную выдачу инструментов хоста; MCP-регистрации сохраняются.

## Разработка

Используйте pnpm **11.19.0**. Версии зависимостей и overrides в `pnpm-workspace.yaml` должны соответствовать одной версии ядра.

```bash
pnpm install --frozen-lockfile
pnpm run typecheck
pnpm run lint
pnpm run test
pnpm run build
pnpm run bench
```

Существующие проверки исходного проекта сохранены. Бенчмарк использует синтетические схемы и не описывает любой реальный каталог инструментов.
